# 시험 대비 빠른 한 장 — 최소 시간, 적절한 시각화

기본 독자는 **블록제 본과생**이다. 시험까지 며칠, 강의는 수십 개. 이 페이지는 «교과서»가 아니라 **강의 하나를 30분에 잡는
지도**다. 디테일보다 **큰 축 + 헷갈리는 것의 감별**이 점수가 된다.
의대 밖(대학원 교재 장, 논문 묶음)도 같은 순서로 만든다. 아래의 「강의안」은 받은 **수업 자료**, 「족보」가 없으면 문제는
「예상 문제」로 표시한다.

## 0. 시작 — 도구 찾기, 시계 켜기

1. **도구 위치.** 이 스킬을 열 때 받은 «Base directory» 를 BASE 라 한다. 템플릿·검사 도구는 다음 순서로 찾아 **처음 쓰는 경로가 실제로 있는지 `ls` 로 확인**한다.
   - `BASE/assets/template.html` · `BASE/scripts/poke.py` (학생 꾸러미)
   - 없으면 `BASE/../interactive-book/assets/template.html` · `BASE/../interactive-book/scripts/poke.py` (플러그인)

   ⛔ **둘 다 없으면 멈추고 말한다. 검사기를 직접 짜지 않는다.** 직접 짠 검사기는 방향 꼴·근거 검사를 빠뜨린다.
   2026-10-13 시험에서 한 세션이 이 스킬 폴더만 보고 템플릿이 없다고 판단해 검사기를 새로 만들었고, 그 페이지는 진짜 poke 에서 돌지 않았다.
2. **시계.** 시작할 때와 보고 직전에 `date` 를 찍는다. 보고의 「걸린 시간」은 두 시각의 차이로 쓴다. 같은 시험에서 여섯 세션 중 다섯이
   어림값을 썼고, 실제(20분)의 두 배(45분)까지 부풀었다.
3. **받은 파일만 출처로 쓴다.** 작업 폴더와 사용자가 가리킨 파일만 읽는다. 디스크를 뒤져 다른 노트·요약을 찾지 않는다.
   다른 파일을 읽었으면 보고에 그 경로와 무엇을 가져왔는지 적고, 페이지 출처에도 적는다.

## 0-1. 시간 예산 — 먼저 지킨다

| 단계 | 예산 |
|---|---|
| 강의안·족보 읽고 «시험 축» 고르기 | 10분 |
| 페이지 만들기(템플릿 채우기) | 20분 |
| poke 검사(방향 포함) + 눈으로 한 번 + 고치기 | 10분 |
| 선생님 확인(확인 목록 5줄) | 5분 — 사람 몫 |

- 시뮬레이터 하나가 **15분 안에 맞게 안 돌면 버리고** 정적 SVG 나 `.compare` 표로 바꾼다. 멋진 것보다 맞는 것.
- 묻지 않고 기본값으로 간다. 꼭 물을 것만 한 줄로: 「이 강의 맞아? 족보 있어?」.
- 한 번에 여러 강의를 받으면 **강의 하나 = 페이지 하나**, 하나 끝낼 때마다 보여 준다(마지막에 몰아서 보여 주지 않는다).

## 1. 무엇을 넣나 — 시험 축만

1. **족보가 있으면 족보부터.** 문항이 반복해서 묻는 개념·수치·감별을 세어 상위 5~8개를 «시험 축»으로 삼는다.
   족보가 없으면 강의안에서 교수가 표·굵은 글씨·그래프로 강조한 것.
2. 축마다 표현을 고른다:

| 시험에서 묻는 모양 | 페이지에서 |
|---|---|
| 그래프·곡선을 읽는 문제(압력-부피, 해리곡선, 용량-반응, 검사값 변화) | **시뮬레이터** — 변수를 끝까지 밀어 그래프가 어떻게 무너지나 |
| 비슷한 둘·셋 감별(질환, 약, 검사 소견) | **`.compare`** — 나란히 두고 다른 칸만 `.diff` 로 칠한다. 토글로 하나씩 가릴 수 있으면 더 좋다 |
| 경로·순서(기전, 진단 알고리즘, 신경 경로) | 누르면 다음 칸이 켜지는 **단계 도식**(SVG + 버튼) |
| 외울 수치·기준 | `.numbers` 상자 몇 개. 시뮬레이터로 만들지 않는다 |

   → **시뮬레이터 0~4개, 감별 1~3개, 문제 5개.** 그 이상 만들지 않는다.
   ⭐ 시뮬레이터로 고르는 조건 둘 — 둘 다 맞아야 만든다. 못 맞추면 정적 그림·`.compare` 표·분류 퀴즈로 간다.
   - 자료에 **양적 관계**(곡선·식·표의 수치)가 있다. 개념·분류·역사 위주의 장은 **0개가 정답**이다.
     같은 시험에서 「2~4개」를 채우려고 개념 장에 고용 곡선·공정 행렬 문턱값을 지어낸 페이지가 나왔다.
   - 「바꾸면 어느 쪽으로」를 자료의 **쪽수·그림·표 번호와 함께** 적을 수 있다(아래 4). 근거를 못 다는 방향은
     확인 목록에 «적고 시뮬레이터는 만들지 않는다» — 적어 두고도 그 위에 시뮬레이터를 세운 페이지가 나왔다.
   ⛔ **자료에 없는 수치를 화면에 내지 않는다.** 자료가 양 끝값만 보고하면 화면에도 양 끝값만 둔다(중간값을 보간하지 않는다).
   자료 범위 밖으로 늘리는 슬라이더를 두지 않는다. 자료가 정하지 않은 기본값(예: 재산 W)을 고르지 않는다 —
   필요하면 자료의 예시 값을 쓰고, 없으면 그 변수를 빼거나 「임의의 예」라고 화면에 쓴다.
   같은 시험에서 기본값 W = L 때문에 손실 뒤 재산이 0이 되어 효용이 무너진 페이지, 자료의 두 끝값 사이를 지어낸 61 %·43 % 가 나왔다.
3. 페이지 순서: 한 줄 요약(이 강의가 답하는 질문) → 시험 축 1…N(축마다 그림 + 2~3문장) → 헷갈리는 것 → **족보형 문제 5개**
   (해설에 «왜 오답인가» 한 줄) → 시험 직전 30초 정리(5줄).

## 2. 정확성 — 강의안이 기준이다

- **정답의 기준은 그 학교 강의안**이다. 교과서와 다르면 강의안 값을 쓰고 작은 글씨로 「교과서(○○)는 ~」를 붙인다. 조용히 고치지 않는다.
- 모든 수치·기준은 강의안 쪽수와 짝지어 둔다 — 페이지 footer 에 「출처: ○○ 강의안 p.12, 15」.
- 족보 문항의 «정답»을 모르면 지어내지 않는다. 「정답 확인 필요」로 표시한다.
- 시뮬레이터 모델은 교육용 근사 — `.sim-note` 한 줄로 밝힌다.

## 3. 문장 — 짧게

평서문, 한 문단 3줄 이하, 이모지 없음. 「~의 핵심은」「A가 아니라 B」「놀랍게도」 같은 말버릇 없이 사실만.
강조 부호 «» 를 쓰지 않는다(poke 가 6개 이상이면 경고한다). 강조가 필요하면 굵게 한두 곳.
용어는 한글(영문) 병기 — 시험지에 나오는 표기로.

## 4. 만들기·검사

- ⭐ **방향부터 적는다(코드보다 먼저).** 시뮬레이터마다 「이걸 바꾸면 저 값은 이쪽으로」를 강의안 근거와 함께
  `<script type="application/json" id="expect">` 에 쓴다(형식: `scripts/poke.py` 머리말, 예시: 템플릿 끝).
  파형의 위상처럼 화면 숫자로 안 보이는 방향은 `K.probe` 로 내놓는다. 그다음 템플릿을 채운다. 상태·컨트롤 먼저, `K.canvas` 마지막.
- 검사 한 줄: `python -X utf8 <0에서 찾은 poke.py> PAGE.html --phone --shots _shots` → **오류 0, 넘침 0, 방향 실패 0**.
  방향 목록이 없거나, 꼴이 틀렸거나(목록이 아닌 객체 등), 줄 이름에 근거(p.12 · 그림 3 · 표 2 · Exhibit 5.5)가 없으면 poke 가 실패한다.
  시뮬레이터가 0개인 페이지는 방향 목록이 필요 없다.
- **나는 그림만 보고는 틀린 생리를 못 잡는다.** 첫 파일럿(중환자감시, 2026-10-13)에서 poke 는 처음부터 오류 0 이었는데
  양압 흡기에 동맥압이 내려가게 그려져 있었다(실제는 흡기에 오른다). 그 뒤 방향 검사 20개를 넣고, 일부러 틀린 사본 셋
  (위상 뒤집기, 용적-PPV 순서 섞기, pH 부호 뒤집기)을 만들어 셋 다 실패하는 것을 확인했다. 새 페이지에서도 부호 하나를
  뒤집은 사본으로 한 번 «실패하는지» 본다.
- ⛔ **방향 목록의 줄마다 강의안 쪽수를 단다.** 기억으로 쓴 줄은 내 오류를 검사로 굳힌다 — 같은 파일럿에서 「COPD → ETCO₂ 높게」를
  기억으로 적어 검사가 통과했는데, 강의안 p.27 그림 B 는 «plateau 없음, ETCO₂–PaCO₂ 차이↑(더 낮다)»였다. PPV 기준도 문헌값 13 % 를
  썼는데 강의안 p.12 표는 반응 >15 %·무반응 <7 % 였다. 쪽수를 못 다는 줄은 확인 목록으로 보낸다.
- PNG 는 배치만 본다: 라벨 겹침, 휴대폰(390px) 글자·버튼, 처음 몇 초 빈 화면, 누른 뒤 변화가 늦게 보이는 버튼
  (파일럿: ROSC 를 누르고 ETCO₂ 가 8–12초 뒤에야 올라 4초로 줄였다).
- **넘기기 전에 «확인 목록» 5줄**을 준다 — 이 강의에서 틀리면 위험한 곳(방향·공식·자료와 다른 값·정답이 불확실한 문항).
  줄마다 «누가 무엇과 대조하나»를 쓴다: 과외면 선생님, 혼자 공부면 본인이 자료 몇 쪽과. 학생에게는 확인된 것만 간다.
- 강의안·족보 정리본에서 «교과서와 다른 곳»을 찾으면 페이지에 작은 경고 상자로 둔다(그날: 좌측 이동 «DPG↑», capnography phase 3 «세포 내 가스»).

## 5. 넘기기 — 공개하지 않는다

- ⛔ **GitHub Pages·공개 링크로 올리지 않는다.** 강의안 그림·족보 문항은 학교와 교수의 것이다.
  결과물은 **HTML 파일 하나**로 공유 폴더(OneDrive 등)에 두거나 비공개 아티팩트로 건넨다.
- 강의안 그림을 페이지에 넣지 않는다 — 필요한 그림은 새로 그린다(SVG). 그래야 파일을 건네도 문제가 없다.
- 파일 이름: `<과목>_<강의 번호 또는 제목>_viz.html`.

## 6. 보고(짧게)

시험 축 N개(족보 근거 몇 문항) · 시뮬레이터/감별/문제 수(시뮬레이터 0개면 왜) · poke 결과(방향 검사 N개) · **확인 목록 5줄** ·
걸린 시간(`date` 두 번의 차이) · 자료와 교과서가 다른 곳 · 받은 파일 밖에서 읽은 것(없으면 「없음」).
