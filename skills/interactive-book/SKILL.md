# 인터랙티브 교과서 — 천천히, 정확하게, 짧게, 보이게

형제: `med-tutor-viz`(과외용 빠른 한 장 — 같은 템플릿). 배포본: github.com/kangdacool/interactive-book-skill
(플러그인 `ibook` — 호출 이름 `/ibook:interactive-book`, `/ibook:med-tutor-viz`). 본보기는 Books 시리즈(books.euiyun.com) — 그 저장소들의 작성 가이드(예: github.com/geniuskey/bodybook
`CONTRIBUTING.md`)가 이 스킬의 뼈대다. **코드 MIT · 본문·그림 CC BY 4.0** 이라 구조를 배우는 것은 자유고, 그 사이트의
글·그림을 «가져오면» 출처 표시가 의무다. 우리는 구조만 배우고 글·그림·코드는 새로 쓴다. 사이트 이름·로고는 쓰지 않는다(사칭).

## 0. 시작 전에 정할 것 — 한 번에 묻는다

| 정할 것 | 기본값 |
|---|---|
| 주제와 «끝나면 답할 수 있는 질문» 3개 | 사용자가 준 주제에서 내가 제안 → 승인 |
| 독자 | 나 자신 / 옆사람(전공 아님) — 사전지식 수준이 용어 풀이 밀도를 정한다 |
| 분량 | **장 3~6개**. 한 장 = 시뮬레이터 4~7 + 정적 그림 1~2 + 퀴즈 3~5 |
| 정본 출처 | 교과서 장·지침·리뷰 2~4개. 사용자가 가진 PDF 가 있으면 그것 |
| 배포 | GitHub Pages 공개. 저장소 이름(영문 소문자·하이픈) |

⛔ **목차(장 제목 + 장마다 시뮬레이터 질문 목록)를 먼저 보여 주고 승인받는다.** 다 만든 뒤 구성을 갈아엎는 것이
가장 비싸다. 그다음 **1장만 완성 → 사용자 확인 → 나머지 장**. 「천천히」는 이 순서를 말한다.

## 1. 정확성 — 쓰기 전에 읽는다

- 출처를 **먼저 읽고** `notes/sources.md` 에 «주장 — 출처(장·쪽 또는 PMID/DOI) — 값» 표로 적는다. 페이지의 숫자는
  전부 이 표에서 온다. 기억으로 쓴 숫자는 없다. 문헌은 PMID/DOI 로 실존 확인(지어낸 참고문헌 금지).
- 시뮬레이터의 모델은 **교육용 근사**다. 어떤 식을 썼고 무엇을 무시했는지 `.sim-note` 에 한 줄로 밝힌다.
  정상 참고값은 readout 옆에 `(참고 …)`로.
- 다 쓰고 나서 **사실 대조 한 번**: 페이지의 숫자·인과 문장마다 sources.md 의 줄을 하나씩 짝짓는다. 짝이 없는 문장은
  고치거나 지운다.
- 의학 주제면 «진단·치료 조언이 아니다» 한 줄(질환을 다루는 장마다 한 번).

## 2. 구조 — 장 하나의 순서

일상의 질문 → 직관(왜) → **시뮬레이터** → 원리(수식은 필요할 때만, 기호마다 단위·대표값) → 실제 수치·정상 범위 →
사례 하나(가상 인물 한 명을 책 전체에서 이어 써도 좋다) → 핵심 정리(3~5줄) → 확인 문제.
- 시뮬레이터 바로 앞에 «무엇을 움직여 볼지», 바로 뒤에 «무엇을 봤는지»를 **2~4문장**으로. 절 하나에 문단 3~6개.
- 용어는 처음 나올 때 `<span class="term">한글</span><span class="en">(English)</span>` + 한 문장 풀이.

## 3. 시뮬레이터 — 이 책의 주인공

- **질문 하나에 시뮬레이터 하나.** 컨트롤 1~4개. 질문이 없는 위젯은 장식이다 — 만들지 않는다.
- **끝까지 밀면 무너지는 모습이 보여야 한다**(포화, 역전, 발산, 경고색 `--bad` + 캔버스 위 한 줄 경고). 한계가 배울 점이다.
- 슬라이더만 있는 것보다 **캔버스를 직접 끄는 것**(곡선 위 동작점, 고리, 구조물)을 우선한다. 끌 수 있는 것에는 손잡이(테두리 원).
- 캔버스 안에 **축 이름·단위·범례·핵심 숫자**를 직접 그린다 — 시뮬레이터만 보는 사람도 혼자 이해되게.
- 결과는 `.sim-readout` 숫자로도. `.sim-note` 는 「해볼 것: ① ② ③」 + 모델 가정.
- 공간 구조(3D 가 본질인 것)는 three.js 모형 하나가 평면 도식 여럿보다 낫다(각도 버튼 몇 개 + 정상/병변 토글).
- 정적 그림(SVG)은 조작이 의미 없을 때만 — 해부도·경로도·비교. viewBox 폭 420~520(휴대폰에서 글자가 산다).
- ⭐ **방향을 코드보다 먼저 적는다.** 시뮬레이터마다 「이걸 이렇게 바꾸면 저 값은 이쪽으로」를 출처와 함께
  페이지의 `<script type="application/json" id="expect">` 에 적고(형식은 `scripts/poke.py` 머리말·템플릿 예시), 그다음 모델을 짠다.
  화면 숫자로 안 드러나는 방향(파형의 위상 등)은 `K.probe.이름 = () => 값` 으로 내놓고 검사한다.
  **방향을 적을 수 없는 시뮬레이터는 만들지 않는다** — 정적 그림이나 비교 표로 간다. 틀린 방향의 모형은 틀린 지식을 가르친다.

## 4. 문장 — AI 티를 빼는 목록

평서문 «~다», 이모지 없음, 짧게. 아래가 보이면 고친다:
- 수사형 제목(「심장이 말하는 것」) → 이름형(「심장 주기」). 「A가 아니라 B」, 콜론 뒤 목록, 「~의 핵심은」, 「놀랍게도」
- 비유를 설명 대신 쓰기(「급한 불」), 같은 말 두 번(앞 문단 요약으로 시작하는 문단)
- 독자가 할 리 없는 질문, 자기 작업 해명(「여기서는 단순화를 위해 ~로 두었다」는 `.sim-note` 로)
- 이중꺾쇠 «» — 페이지 표면에는 ‘ ’ 나 굵게
한국어 문장 검사기(`korean-prose` 스킬의 kprose 등)가 있으면 페이지 글에 돌려 FAIL 0 을 확인한다.

## 5. 만들기 — 템플릿에서 시작

- `assets/template.html` 을 복사한다. 한 파일 = 한 장. 여러 장이면 `index.html`(목차) + `chapters/NN-slug.html`.
  공용 도우미 `K`(canvas·sliders·seg·drag·loop·axes)와 컴포넌트(.sim, .compare, .callout, .numbers, 퀴즈)를 쓴다.
- 색은 토큰(`--acc` 등)만 — 다크 모드가 공짜로 된다. 캔버스는 `K.color('--acc')`.
- 시뮬레이터 하나 = IIFE 하나. **상태·컨트롤을 먼저 만들고 `K.canvas` 는 마지막에**(만들자마자 그린다 — 템플릿에서 실제로 난 오류).
- 외부 라이브러리는 CDN(jsdelivr) 만, ES module 쓰지 않는다(file:// 로도 열려야 한다).

## 6. 검사 — 고칠 때마다

```bash
python -X utf8 scripts/poke.py PAGE.html                 # 방향 검사 + 모든 슬라이더 최소·최대, 버튼·선택·끌기 → 오류 0, 넘침 0, 방향 실패 0
python -X utf8 scripts/poke.py PAGE.html --phone --shots _shots --full _shots/page.png   # 390px + 시뮬레이터별·전체 PNG
```
(`scripts/` 는 이 스킬 폴더 기준. 필요: `pip install playwright` + `python -m playwright install chromium`.)
- ⭐ **나는 그림을 보고 틀린 생리를 잘 못 알아챈다** — 첫 파일럿에서 오류 0 인 채로 동맥압 파형이 거꾸로였다.
  그래서 «맞는지»는 방향 검사(숫자)와 사람의 확인이 본다. 방향 검사는 그 페이지에 일부러 틀린 사본(부호 하나 뒤집기)을
  한 번 만들어 «실패하는지» 확인한다 — 안 걸리면 검사가 빈 것이다.
- PNG 는 배치만 본다 — 라벨이 겹치나, 휴대폰에서 버튼이 눌리나, 다크 모드에서 보이나, 처음 몇 초 비어 보이지 않나,
  버튼을 누른 뒤 변화가 몇 초 안에 보이나.
- **완료라고 말하기 전에 사용자에게 «확인 목록»을 준다** — 이 장에서 틀리면 위험한 곳만 5줄 이내(방향·공식·출처와 다른 값).
  사용자가 본 뒤에 배포한다.

## 7. 배포 — GitHub Pages

```bash
python -X utf8 scripts/deploy_pages.py SITE_DIR repo-name          # 점검: 올라갈 파일·이미지·공개 주소
python -X utf8 scripts/deploy_pages.py SITE_DIR repo-name --yes    # 사용자 승인 뒤에만
```
- ⛔ **공개 배포는 사용자에게 저장소 이름과 파일 목록을 보여 주고 «올려»를 받은 뒤**에. 원본 문서(.pdf .pptx .docx .hwpx)는
  스크립트가 막는다. 이미지는 직접 만든 것·라이선스가 맞는 것만(출처를 footer 에).
- footer: 출처 목록 + 「시뮬레이터 수치는 교육용 근사 모델」 + 구조를 배운 곳(「구성은 Books 시리즈에서 배웠다」 한 줄은 예의).
- 배포 뒤 공개 주소를 한 번 `poke.py` 가 아니라 실제 브라우저로 열어 확인하고 주소를 보고한다.
